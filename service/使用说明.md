# Codex Remote 电脑服务使用说明

这份服务包用于让手机连接你的开发电脑，在电脑上读取并继续 Codex 会话。同一份 ZIP 支持 macOS、Linux 和 Windows；包含本机 Agent、中转服务、手机客户端网页版，以及本机管理页。

## 第一次使用

1. 安装 Node.js **22.13 或更新版本，建议 24**。
2. 安装并配置支持当前项目接口的 Codex CLI。本服务已验证 **0.162.0-alpha.17.2**，可运行 `npm install -g @openai/codex@0.162.0-alpha.17.2` 安装；确认 `codex --version` 并完成你的模型提供商设置、认证，能够正常使用 Codex。[官方 CLI 安装说明](https://learn.chatgpt.com/docs/codex/cli)。
3. 把 `codex-remote-service.zip` 完整解压到一个固定目录。服务包已经包含程序依赖和网页版，无需 `npm install`、Expo 或 Android SDK。
4. 运行对应启动文件：

| 系统 | 启动方式 |
| --- | --- |
| Mac | 双击 `service/Start-Mac.command` |
| Windows | 双击 `service/Start-Windows.cmd` |
| Linux | 在解压目录运行 `bash service/Start-Linux.sh` |

启动文件会启动后台服务，再打开本机浏览器管理页。管理页显示电脑名称、在线状态、服务端口、所在目录、启动命令和实际日志，并有启动、停止按钮。管理页地址只对本机开放；手机使用管理页中显示的 **手机连接** 地址。

关闭启动终端或管理页后，后台 Agent 继续运行。电脑重启后，再运行启动文件。服务以当前登录用户运行，沿用该用户的 Codex 配置、会话与文件访问权限。

Mac 的启动文件保留可执行权限。如果解压工具没有保留权限，可在解压目录运行 `chmod +x service/Start-Mac.command`。

## 手机怎么连接

1. 手机与电脑连接同一个 Wi-Fi。
2. 在解压目录打开终端，运行 `npm run connection`，查看 **服务地址** 和 **配对密钥**。
3. 手机 App 进入 Settings，填入这两项，保存并连接。
4. 进入 Projects，选择这台电脑上的项目与会话。

也可以在解压目录运行 `npm run pairing`，生成 `.local/pairing-app.png` 配对二维码。网页版地址在管理页显示，电脑和手机浏览器均可打开。

当前服务使用通信协议 **2**，手机 App 需要对应新版客户端；旧正式 APK 需要重新安装新版。开发 APK 通过源码项目的 Metro 加载新 JavaScript。手机也可以直接使用服务包自带的网页版。

配对密钥与二维码保存在本机 `.local/`，每台新安装的服务包首次启动生成自己的配对信息。重启服务保留原来的密钥和机器 ID。手机连不上时，先检查服务是否显示 Agent 在线、地址是否包含实际端口，以及电脑防火墙是否允许该端口的局域网访问。

## 统一操作命令

在解压目录打开终端，三种系统使用同样的命令：

```bash
npm run service:start       # 后台启动；已运行时不会重复启动
npm run service:status      # 查看进程、Agent、中转与手机连接地址
npm run service:console     # 打开管理页服务，点击终端显示的本机地址
npm run service:logs        # 显示最近的正常日志和错误日志
npm run service:logs -- --follow  # 持续刷新日志，Ctrl+C 退出查看
npm run service:stop        # 停止本机服务及其子进程
npm run service:doctor      # 检查 Node、Codex 和网页版文件
```

日志位于解压目录下的 `.local/service.log` 和 `.local/service-error.log`。每条日志记录 UTC 时间；管理页的启动时间按浏览器本地时间显示。单个日志超过 2 MB 时保留上一份 `.1` 日志。错误日志保留历史记录，判断当前状态时同时查看时间与 Agent 是否在线。

## 自定义 Codex 路径与端口

在解压目录的 `.local/service.env` 写入需要调整的设置，停止后再启动服务生效。这份文件不会包含在交付 ZIP 中。

```dotenv
CODEX_BIN="/你的实际路径/codex"
RELAY_PORT=8788
DEVICE_NAME="我的开发电脑"
```

Windows 的 Codex npm 安装入口 `.cmd` 和原生 `.exe` 均由跨平台进程库启动，路径有空格也可使用。Mac 可填写你实际使用的 Codex 可执行文件绝对路径。`PUBLIC_HOST` 可指定手机能访问的电脑局域网地址；默认从系统网卡读取。

项目和会话来自运行 Agent 的系统及其 `CODEX_HOME`。Windows 桌面 Codex 通常使用 `C:\Users\用户名\.codex`，WSL 使用 Linux 用户的 `~/.codex`；即使打开同一份仓库，两套项目列表也不会自动同步。要读取 Windows 桌面数据，请在 Windows 启动服务，并在 `.local/service.env` 指定桌面实际使用的 `CODEX_BIN` 和必要时的 `CODEX_HOME`，然后停止、重新启动。Windows 本机服务不自动读取桌面连接的远程 SSH 主机数据，各主机需要自己的 Agent。

## 另一台电脑只接入已有中转

服务包也包含独立 Agent 入口。只接入已有中转时，在终端设置 `REMOTE_TOKEN`、`RELAY_URL`、`DEVICE_NAME`，然后运行 `npm run agent`。具体连接方式与源码项目 README 的“添加其他电脑”一致；集成的双击启动方式用于在本机同时运行 Agent 与中转。

## 源码项目的使用

源码目录首次运行需要 `npm ci` 和 `npm run web:build`，之后可以使用上述 `service:*` 操作命令，也可以双击源码目录里的 `service/Start-Mac.command`。`npm start` 保留前台启动；手机快速刷新继续使用 `npm run dev`。

在源码项目运行 `npm run service:build` 会生成 `artifacts/codex-remote-service.zip` 与对应 SHA-256 文件。只收录构建程序、网页版、通用启动文件及本文档，不收录本机配对信息、日志、Codex 凭据或会话。
